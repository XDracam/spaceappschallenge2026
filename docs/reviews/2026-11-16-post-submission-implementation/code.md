# Reliability implementation — 2026-11-16

## Implemented

- **R-21:** `planner/physics/evaluate.ts` records whether a matching goal location/altitude was actually reached before selecting an earlier altitude failure. Missing optional instruments now receive the existing instrument explanation. Only the failure-reason path changed: no achievable flags, factors, probabilities, rolls, physical calculations or scoring were edited.
- **R-22:** `core/store.ts` derives remote action actor from the host's own peer-to-seat map. Existing lobby/free-seat claim must name the sending peer; seated clients may dispatch their own station namespace or shared coordination. Remote core host controls and other stations' mutations are explicitly rejected. Existing trusted local host controls remain.
- **R-23:** `core/validation.ts` provides a small explicit action-argument vocabulary, bounded recursive finite JSON checks (20 levels, array/object entry bounds, 32K strings, action 64K), prototype-key rejection, maneuver/enum/nested-object checks, and current-state shape validation. Each action signature was compared against actual registered reducers. Debug mutations have validated DEV-only entries and are absent in production. A rejected action ID is removed from the client's optimistic queue and an in-app explanation is exposed. Disconnected/128-pending clients cannot accumulate unlimited optimistic work. Reducer exceptions are caught before authoritative assignment, with clear rejection.
- **R-23 framing:** `net/framing.ts` shares the existing JSON wire representation across PeerJS and manual WebRTC. It validates indexes/counts/types, rejects duplicate/inconsistent chunks, bounds each assembly to 8 MiB/525 chunks and each connection to 4 incomplete assemblies, expires them after 30s, and clears them on close. Invalid framing or send failure closes the affected link instead of silently retaining a broken channel. Early pre-listener messages are bounded to eight. Manual code input is bounded to 200K characters; compression/decompression output is limited to 1 MiB while streaming.
- **R-24:** `core/persist.ts` validates migrated saves before adoption, exposes `saveLoadIssue`, retains unreadable raw records, offers `downloadSavedRecord(): boolean`, and blocks automatic replacement until explicit `clearSaved()`. Successful explicit clearing also cancels pending save timers so an old record is not resurrected on pagehide. Existing save migration order is retained.
- **R-25:** `core/build.ts` consumes root-owned Vite `__MC_BUILD_ID__`; protocol compatibility is `2:<deterministic source hash>`. Welcome/hello must agree before a snapshot is sent or adopted. Both existing client transports add compatibility automatically to shell hello. A mismatching or unreadable host version gives a specific in-app reload/save/rejoin explanation through `syncStore.error` and disables client dispatch. Room-code reconnection reaches an error state after 12s; retry reconnects the existing broker peer without destroying healthy game links, and manual invites remain available.
- **Related serializer correction:** JSON represents optional array `undefined` slots as `null`. All current action signatures were inspected: no required argument permits null. `applyAction` restores top-level null slots to omitted-argument semantics, after required-argument validators reject null. Nested optional state fields still reject null unless explicitly nullable (seats, launch history). This fixes network request default-argument handling while preserving local semantics.
- **C14:** assigned to UI technical/Procurement owner because rules.ts lies outside this packet's edit boundary. **C12:** root owns the narrow derive.ts mission-context adjustment. **Ion anomaly:** untouched/deferred.
